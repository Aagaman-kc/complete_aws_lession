# 02 — EC2 (Elastic Compute Cloud)

## Theory

### What is EC2?
- Virtual servers in the cloud
- Choose OS (Amazon Linux, Ubuntu, Windows), CPU, RAM, storage
- Billed per second/minute

### Instance Types
- **General purpose** — t2, t3, m5 (balanced)
- **Compute optimized** — c5 (CPU-heavy)
- **Memory optimized** — r5, x1 (RAM-heavy)
- **Storage optimized** — i3, d2 (disk I/O-heavy)

### AMI (Amazon Machine Image)
- Pre-configured OS + software template
- Quick Start: Amazon Linux 2, Ubuntu 22.04, etc.
- Marketplace: third-party images
- Custom: your own saved AMI

### Key Pairs (SSH)
- **Private key** → you keep it, never leaves your machine
- **Public key** → AWS stores it on the instance at `~/.ssh/authorized_keys`
- Used for password-less SSH login

#### How RSA Signing Works
1. Server sends a challenge (random number)
2. Your laptop signs with private key: `signature = message^d mod n`
3. Server verifies with public key: `message = signature^e mod n`
4. Match = identity proven, private key never transmitted

| Key | Role | Who Has It |
|-----|------|-----------|
| Private Key | Creates signatures | You |
| Public Key | Verifies signatures | AWS |

Security relies on: multiplying primes is easy, factoring their product is hard.

### Security Groups
- Virtual firewall at the instance level
- Default: deny all inbound, allow all outbound
- Rules are allow-only (no deny rules)
- Stateful — return traffic is automatically allowed

### User Data
- Script runs at first boot (or every boot if configured)
- Used for bootstrapping: install packages, run services

### Instance Metadata
- Accessible from inside the instance: `http://169.254.169.254/latest/meta-data/`
- Contains instance ID, AMI ID, public IP, etc. (no auth required from inside)

### Elastic IP

| Feature | Dynamic Public IP | Elastic IP |
|---------|-----------------|-----------|
| Assigned by | AWS automatically | You (reserved to account) |
| Changes on stop/start | Yes | No |
| Movable between instances | No | Yes |
| Best for | Testing | Production |

- Elastic IP = static public IPv4 reserved to your AWS account
- Charge applies if allocated but not attached to a running instance
- Modern best practice: use a **Load Balancer** instead of exposing EC2 directly

## Project — Deploy K8s App on EC2

### Architecture

```
Internet → EC2 (Public IP) → Ubuntu → Docker → kind (K8s cluster)
                                                      │
                                            Ingress (single endpoint)
                                                  ├──────────┐
                                                  ▼          ▼
                                             Frontend     Backend (replicas)
                                                              │
                                                         PostgreSQL
                                                              │
                                                         PVC + PV (persistent)
```

### Objective
Deploy the full K8s application (frontend + backend + PostgreSQL) on a single EC2 instance using kind (Kubernetes-in-Docker).

### What You'll Practice

**AWS**
- Launch EC2, SSH, Security Groups, EBS storage, public IP, user data

**Linux**
- Package installation, Docker, kubectl, kind

**Kubernetes** (already learned)
- Deployments, Services, StatefulSet, PVC, ConfigMap, Secret, Ingress

### Steps

#### 1. Launch Ubuntu EC2 instance (t3.medium or larger)
- Use Security Group allowing SSH (22) and HTTP (80)
- Download the `.pem` key pair

#### 2. Copy the project to the instance via SCP
```powershell
scp -i C:\Users\Aagaman\downloads\learning.pem -r 10.production-readiness ubuntu@98.81.189.194:~/
```

#### 3. SSH into the instance and set up dependencies
```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y docker.io
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
newgrp docker

# kubectl
curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
chmod +x kubectl && sudo mv kubectl /usr/local/bin/

# kind
curl -Lo ./kind https://kind.sigs.k8s.io/dl/v0.20.0/kind-linux-amd64
chmod +x kind && sudo mv kind /usr/local/bin/
```

#### 4. Create a kind cluster with port mapping
```bash
cat <<EOF > kind-config.yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
- role: control-plane
  extraPortMappings:
  - containerPort: 30080
    hostPort: 80
    protocol: TCP
EOF

kind create cluster --name prod --config kind-config.yaml
kubectl create namespace production
kubectl config set-context --current --namespace=production
```

#### 5. Build Docker images and load them into kind
```bash
cd 10.production-readiness/backend
docker build -t fastapi-backend:2.0 .
kind load docker-image fastapi-backend:2.0 --name prod

cd ../frontend
docker build -t frontend:1.0 .
kind load docker-image frontend:1.0 --name prod
```

#### 6. Apply all K8s manifests
```bash
kubectl apply -f k8s/config-and-secret.yaml
kubectl apply -f k8s/postgres.yaml
kubectl apply -f k8s/backend.yaml
kubectl apply -f k8s/frontend.yaml
```

#### 7. Install and configure Ingress Controller
```bash
kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/main/deploy/static/provider/kind/deploy.yaml
kubectl -n ingress-nginx wait --for=condition=ready pod --selector=app.kubernetes.io/component=controller --timeout=120s
kubectl -n ingress-nginx patch svc ingress-nginx-controller -p '{"spec":{"type":"NodePort","ports":[{"name":"http","port":80,"targetPort":80,"nodePort":30080},{"name":"https","port":443,"targetPort":443,"nodePort":30443}]}}'
kubectl apply -f k8s/ingress.yaml
```

#### 8. Install Metrics Server and HPA
```bash
kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
kubectl -n kube-system patch deployment metrics-server --type=json -p='[{"op": "add", "path": "/spec/template/spec/containers/0/args/-", "value": "--kubelet-insecure-tls"}]'
kubectl autoscale deployment backend --cpu-percent=50 --min=2 --max=5
```

#### 9. Verify
- Visit `http://<EC2-PUBLIC-IP>` — app is live on real AWS
- `kubectl get pods` should show backend (×2), frontend, postgres all Running
